# COCOA-10.11-SURFACE-PLAN.md's S2 tier says availability and deprecation annotations ARE part of the surface, for a
# reason that is not pedantry: 10.11 is the last classic-Objective-C SDK, its headers carry the facts that make the
# surface usable, and a client cannot tell a 10.0 door from a 10.11 one without them. This tree's macros were INERT BY
# DECISION (NSObjCRuntime.h, D12) until this slice; they now expand to clang's availability attribute through
# `libagora-core`'s CFAvailability.h, and this file pins what that made measurable.
#
# THE REFERENCE IS THE SAME 10.11 MANIFEST, and the versions are committed beside the names: `class-era` and
# `selector-era` lines in api/10.11/foundation-manifest.txt carry Apple's introduction and deprecation tokens verbatim
# (`10_6`, and `-` for no deprecation). That is what lets this gate run WITHOUT an SDK checkout — the alternative, a
# sweep annotated from memory, is exactly the drift the plan's S2 tier forbids.
#
# THE DENOMINATOR IS WHAT THE TREE ACTUALLY DECLARES. A declaration this tree does not have cannot be annotated, so
# the candidates are the declarations both sides have: 800 of them. The rest of Apple's annotated surface is on classes
# this tree has yet to write (the 26 in FOUNDATION-10.11-PLAN.md §3.1) or in spellings this reader does not attribute
# (an `NS_ENUM` constant is not a selector).
#
# **THE SWEEP IS COMPLETE, AND IT WAS 761 DECLARATIONS IN 108 HEADERS.** The first pin of this file read 802
# candidates / 0 present / 802 missing; the sweep then turned every candidate into a stated fact, and the 35-candidate
# difference is two attribution faults it exposed: a category's availability was being recorded as its CLASS's era
# (NSArray is not a 10.6 class — Apple annotates the `NSExtendedArray` category), and a forward `@protocol X;` was
# being read as a block, which attributed NSXMLParser's doors to its DELEGATE. Both were in the instrument, both were
# fixed before the sweep was applied, and the manifest regenerated between.
#
# **THE SPELLING IS `NS_AVAILABLE_MAC` / `NS_DEPRECATED_MAC` / `NS_CLASS_AVAILABLE_MAC`, NOT THE TWO-ARG FORM.** The
# manifest commits the macOS token; the iOS one is a fact this reference records but this tree has no use for, and
# writing it from memory would be the invented annotation the plan forbids. The tree targets one platform, so the
# Mac-only spelling states exactly the fact that is known.
#
# **TWO OF THESE NUMBERS MEAN DIFFERENT THINGS, AND THAT IS THE WHOLE DESIGN.**
#
#   * `annotations-wrong` is a FAILURE, in either mode, and is not a number this file can raise. A declaration that
#     states a version Apple does not is worse than one that states none: it looks finished. The command exits
#     non-zero on it and names the first twenty, reference and local side by side.
#   * `annotations-missing` is the SWEEP'S WORK LIST, and pinning it is what makes progress a deliberate act. It read
#     802 at the start of W1 (the macros real, nothing using them) and 0 after the sweep. It may only FALL, and a new
#     declaration for an annotated Apple door raises it again — which is the gate doing its job on the wave that added
#     the declaration, not a false alarm.
#
# `annotations-extra` counts declarations this tree annotates that Apple does not. It is not a failure: the tree ships
# API that postdates 10.11 (`NSDateInterval`, a `NSRelativeDateTimeFormatter`) and FOUNDATION-10.11-PLAN.md §4.13 says
# such a door is annotated with the version it really arrived in. The count is here so that it is a number rather than
# a surprise.
#
# A DECLARATION IS MATCHED WHERE IT IS WRITTEN. Inheriting `-bytes` from `NSData` is not a declaration site, so the
# comparison uses each class's OWN selector set rather than its inheritance closure — the opposite of the surface
# census, which resolves inheritance because that is what `respondsToSelector:` answers. Two questions, two rules.
#
# **THE DESIGNATED-INITIALIZER FACTS ARE COUNTED HERE TOO, AND THE SWEEP IS UNDER WAY BY CLASS.** `NSURL` is the first
# class done: its eight doors are marked, its parse became a plain method so each door could be its own constructor
# (the rule in §4.15 of the plan), and this file moved from 135/2 to 127/10 in that commit.
# `designated-extra` counts a tree-local mark only when the selector is CLASS-OWNED in the manifest, so
# NSMachPort's three restated socket doors are not counted: they are inherited selectors. `NSSocketPort` then marked
# its three doors (local address, local socket, remote address) in batch 5b: `-init` and `-initWithTCPPort:` route to
# the local address door, and `initRemoteWithTCPPort:host:` walks `getaddrinfo`'s answer list and hands the descriptor
# that connected to the designated socket door. Batch 6 then marked `NSDataDetector`'s one door (nothing else in that
# class initialises), `NSDate`'s reference-date door (which became the storage constructor, with 1970 as a convenience
# route), and `NSString`'s `-init`/`-initWithCoder:`; the string front's re-routing convenience doors each delegate to
# the designated `-init` before handing off to `NSOwnedString`, which is what a cluster's door has to say out loud.
# Batch 7 closed the "route to a marked door" group (NSIndexPath, NSIndexSet, NSInputStream, NSOutputStream, NSBundle)
# and `NSAppleEventDescriptor`, whose Apple-marked door can only refuse here, so that header RESTATES and marks `-init`
# as this tree's constructor — which is why methods-declared moved 4,045 -> 4,046.
# Batch 8 closed the "extract or flip" group: NSAppleScript, NSComparisonPredicate, NSLocale, NSNotification,
# NSHashTable, NSMapTable and NSPointerArray each have TWO designated doors where one used to chain to the other, so the
# shared install became a plain method and each door states it; NSExpression's coder door routes through the designated
# type door; NSFileHandle's coder door is a raise-only refusal and keeps a local pragma.
# Batch 9 placed the last 29 marks, all of them declarations whose bodies already conformed (the measurement found no
# warnings), with one knock-on: NSDataDetector is an NSRegularExpression subclass, so marking NSRegularExpression's
# designated pattern door obliged the detector to override it. A data detector has no pattern, so that override is a
# refusal with an error naming -initWithTypes:error:, and the detector's own designated door chains to the super's with
# the empty pattern (state every matching door on the class bypasses).
#
# **THE SWEEP IS FINISHED, AND THE ONLY MARKS LEFT OUT ARE THE NUMBER CLUSTER'S.** `designated-init` is a different
# kind of fact from an era: it carries no version, it says which initializer defines the class's state. Apple marks 182
# in the 10.11 Foundation; 178 reach the manifest after ownership and availability filtering, and 143 of them are on
# declarations this tree makes. Sweeping them was ATTEMPTED first and the result recorded rather than hidden: with the
# marks in place the library built, but clang emitted **202 distinct declaration sites** of
# `-Wobjc-designated-initializers` — "designated initializer should only invoke a designated initializer on 'super'",
# "convenience initializer missing a 'self' call to another initializer", and so on. Those warnings were TRUE: this
# tree's initializers did not follow the graph Apple's marks describe, and marking the header without fixing the bodies
# would have stated a contract the implementations broke. Nine batches later the bodies comply and the library emits
# **zero** such diagnostics with every mark placed. The 18 missing marks are deliberate: `NSNumber`'s 16 and
# `NSDecimalNumber`'s 2, the re-routing class cluster refused by decision in FOUNDATION-10.11-PLAN.md §4.15 — Apple's
# marks describe a cluster whose storage lives in Core Foundation, where no clang rule applies; this cluster's storage
# lives here.
#
# THE GATE is `foundation-api-availability` in tests/CMakeLists.txt, which runs `api-ledger availability` with `--pin`
# and fails on drift in either direction as well as on a wrong version.
